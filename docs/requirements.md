# 知擎智能问答系统产品需求文档（PRD · v1.0）

## 1. 项目概述

### 1.1 产品背景
企业内部制度与办事流程分散在 IT、OA、HR、财务、法务、信息安全、行政等多个职能部门，
员工遇到"VPN 连不上、年假怎么算、报销发票要求、会议室怎么订"这类问题时，
往往要翻文档、找群、提工单，人工答疑重复且响应慢。知擎面向企业内部知识库，
把高频问题做成标准问答（FAQ）、把制度文档做成可检索的知识库（RAG），
提供 7×24 小时的自助问答，减少重复人工答疑、提升办事效率。

### 1.2 产品目标
- **自助即时**：高频问题秒级命中标准答案，低频问题检索制度文档后生成回答。
- **减轻人工**：把 IT 服务台/职能部门的重复答疑沉淀为知识库，降低工单量。
- **答案可信**：回答附带引用来源，可回溯到原文片段，避免"凭空作答"。
- **知识沉淀**：制度文档与问答记录统一入库，可审计、可分析、可持续扩充。

### 1.3 目标用户
- **主要用户**：企业员工（尤其新员工，入职/办事高频查询）。
- **次要用户**：IT 服务台、HR、行政、财务等职能人员（维护知识、处理兜底工单）。
- **使用场景**：办公网/VPN 故障自助排查、考勤假期与审批查询、报销差旅规则、
  会议室与资产领用、信息安全须知、合同用印流程等。

### 1.4 知识范围（7 个知识域）
`it`（网络/账号/权限/邮箱/软件）、`oa`（考勤/假期/审批/出差/公告）、
`hr`（入职/离职/福利/薪酬/绩效）、`finance`（报销/发票/预算/付款/采购）、
`legal`（合同/用印/合规/知识产权）、`security`（钓鱼/泄露/外发/加密/病毒）、
`admin`（会议室/资产/办公用品/车辆/门禁/访客/食堂）。
知识库规模小（30 份制度文档 + 80 条标准 FAQ），采用 bge-m3 单向量直接召回。

## 2. 产品功能需求

### 2.1 用户交互功能

#### 2.1.1 首页访问
- **用户故事**：作为员工，我希望打开页面就能提问，快速获得办事指引。
- **验收标准**：页面加载 < 2 秒；界面清晰易用；支持 PC 与移动端浏览器。

#### 2.1.2 登录鉴权
- **用户故事**：作为管理员，我希望知识库仅对授权用户开放，避免内部制度外泄。
- **功能描述**：账号口令登录换取 JWT；业务接口校验 Bearer token，
  WebSocket 握手校验 `?token=`；未授权统一返回 401。
- **验收标准**：登录成功签发 token；缺失/无效 token 被拒；token 过期需重新登录。

#### 2.1.3 会话管理
- **用户故事**：作为员工，我希望系统记住对话历史，以便延续之前的话题。
- **会话创建**：自动生成 UUID 作为 session_id，创建无感知，支持多个并行会话。
- **历史查看**：按会话拉取最近若干轮问答，时间正序展示。
- **历史清除**：软删除（打标记，不物理删除），清除后立即生效，数据仍可审计。

### 2.2 智能问答功能

#### 2.2.1 问答查询
- **用户故事**：作为员工，我希望输入问题就能得到准确、可溯源的答案。
- **功能描述**：双通道——FAQ 精确问答（命中标准问句直接回标准答案）+
  RAG 检索增强（向量召回制度文档片段，交在大模型生成，附引用来源）。
- **验收标准**：答案与问题相关；引用来源可回溯原文；域外/信息不足时走兜底话术而非编造。

#### 2.2.2 交互方式
- **即时回答模式**：FAQ 命中或问候语，一次性返回完整答案，响应快。
- **流式回答模式**：需要 RAG 时走 WebSocket，逐 token 输出（start → token* → end），
  首包快、体验自然；`end` 事件携带引用来源与意图。

#### 2.2.3 意图识别与知识域路由
- **功能描述**：关键词规则为主 + 轻量文本分类（TF-IDF/逻辑回归）判"通用知识/专业咨询"；
  通用知识不查库直接作答，专业咨询按关键词路由到知识域后检索。不做大模型微调。
- **验收标准**：企业制度类问题能进入检索；常识/问候类问题不触发无谓检索；
  分类器误判时关键词规则能兜底纠偏。

#### 2.2.4 知识域过滤
- **用户故事**：作为员工，我希望指定知识域提问，获得更精准的答案。
- **验收标准**：支持 7 个知识域选择；未显式选域时按意图自动路由；跨域问题可不限域检索。

#### 2.2.5 问候识别
- **功能描述**：识别"你好/在吗"等日常问候，友好回应，不触发检索。

### 2.3 系统管理功能

#### 2.3.1 系统状态监控
- **功能描述**：提供健康检查接口，反映服务与依赖状态。
- **验收标准**：探针可快速判活；异常时日志可定位（trace_id 串联）。

#### 2.3.2 知识域列表
- **功能描述**：展示当前支持的知识域，供前端过滤选择。
- **验收标准**：列表与配置一致、准确完整。

#### 2.3.3 知识库维护（离线）
- **功能描述**：制度文档入库（Markdown/PDF/DOCX 加载、分块、向量化）、
  FAQ 标准问答导入、意图分类器训练、RAGAS 离线评测，均以脚本方式执行。
- **验收标准**：入库幂等（重复执行不产生重复数据）；导入/训练结果可核对。

## 3. 产品原型设计

界面预览见 `img/ui-preview.png`。

### 3.1 首页/会话界面
- **布局**：聊天式对话界面。
- **元素**：知识域选择、输入框、发送按钮、问题/答案气泡、引用来源卡片、清空会话。
- **交互**：输入后回车或点击发送；流式逐字渲染；点击来源可定位原文片段。

### 3.2 知识域选择
- **布局**：下拉菜单或标签。
- **元素**：7 个知识域标签 + "不限"。
- **交互**：选择后应用到后续提问（作为 subject 过滤）。

## 4. 用户体验需求

### 4.1 易用性
- 核心操作不超过 3 步；操作有明确反馈，流式输出有进度感。

### 4.2 响应性（目标值，需真实环境实测校准）
- 页面加载 < 2 秒；FAQ 即时回答 < 2 秒；RAG 流式首包 < 1 秒；
- 单请求 RAG 端到端约 3 秒（GPU；含检索 + 生成，具体由模型生成速度决定）。

### 4.3 可访问性
- 支持 PC/平板/手机与主流浏览器；界面符合基本无障碍标准。

## 5. 业务指标

### 5.1 服务指标
- **自助解决率**：无需转人工即可解答的问题比例。
- **人工工单量**：IT 服务台/职能部门重复答疑工单的下降幅度。
- **平均响应时间**：FAQ 命中耗时、RAG 端到端耗时。

### 5.2 质量指标
- **答案相关性 / 上下文召回**：以 RAGAS 离线评测衡量（30 条评测集）。
- **引用可回溯率**：回答附带可定位原文来源的比例。
- **员工满意度**：问答后的反馈评分。

### 5.3 知识指标
- **知识覆盖率**：7 个知识域文档与 FAQ 的覆盖与更新情况。
- **兜底率**：信息不足/域外问题走人工客服兜底的比例（越低越好，但不应靠编造降低）。

## 6. 价值

- **成本节约**：减少重复人工答疑，释放 IT 服务台与职能部门人力。
- **效率提升**：员工自助即时获取制度指引，缩短办事与入职适应周期。
- **知识资产**：制度与问答统一沉淀，可审计、可分析、可持续扩充。

## 7. 产品路线图

### 7.1 MVP
- 基础问答（FAQ + RAG）、会话管理、简洁聊天界面。

### 7.2 v1.0（当前版本）
- 7 知识域过滤与意图路由、WebSocket 流式输出、引用来源可回溯、
  JWT 鉴权、bge-m3 单向量检索、33 个 pytest 用例、RAGAS 离线评测。

### 7.3 后续演进（知识库规模增大后再引入）
- 混合检索（稠密 + 稀疏）与重排序、父子分块、查询改写/规划、
  反馈闭环与知识自动更新、多账号与权限分级。
