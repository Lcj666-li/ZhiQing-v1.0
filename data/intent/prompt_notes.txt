意图分类数据集生成说明（data/intent/intent_dataset.jsonl）
======================================================================

任务：为"通用知识 / 专业咨询"二分类器构造标注数据。
分类器用途：判断一句 query 是否需要查企业知识库——
  · 通用知识：数学计算、代码生成/纠错、计算机概念与原理、常识、问候、
    创意写作、翻译等，不落在企业制度范围内，直接交给大模型作答；
  · 专业咨询：企业内部 IT 服务台知识库覆盖的业务问题，需要走 RAG 检索。

【专业咨询的 7 个知识域】（与 config.ini 的 valid_sources、
app/rag/intent.py 的 DOMAIN_KEYWORDS、data/kb/{域}_data 文档一一对应）
  it       网络/VPN、域账号与密码、权限、共享盘、打印机、邮箱、投屏、
           WiFi/证书、U 盘、工单、蓝屏、软件安装与正版化
  oa       考勤/打卡、请假/年假/调休/加班、审批流程、出差/外勤、内部公告/通知
  hr       入职/离职/转正、福利/培训/体检、社保/公积金、工资/薪酬、绩效/试用期
  finance  报销/发票/差旅、预算、对公付款/借款、费用、采购/供应商结算
  legal    合同审查/签署、用印/盖章、法务/合规、知识产权/商标/专利
  security 钓鱼邮件、账号泄露、数据外发/脱敏、信息安全、加密、病毒/中毒应急
  admin    会议室、资产/办公用品、车辆/用车、工位、门禁/访客、食堂

【构造要求】
1. 两类数量均衡（本数据集为通用知识 105 条 + 专业咨询 105 条，共 210 条），
   专业咨询尽量覆盖全部 7 个域，措辞多样（疑问句/陈述句/口语化均可）。
2. 专业咨询的 query 应命中 DOMAIN_KEYWORDS 里的特征词，保证关键词规则
   （is_domain_query / route_domain）能兜底纠偏；通用知识的 query 刻意
   避开这些特征词，防止规则把常识问题误判成需要查库。
3. 每条输出为 JSON：{"query": 原始问句, "label": "通用知识" 或 "专业咨询"}，
   一行一条（JSONL），UTF-8 编码，不含多余字段。
4. 不堆砌重复句式凑数；宁缺毋滥，保证多样性与标注一致性。

【示例】
  {"query": "VPN 连不上怎么办？", "label": "专业咨询"}
  {"query": "差旅报销的发票有什么要求？", "label": "专业咨询"}
  {"query": "怎么预订会议室？", "label": "专业咨询"}
  {"query": "1024 乘以 768 等于多少？", "label": "通用知识"}
  {"query": "用 Python 实现快速排序。", "label": "通用知识"}
  {"query": "帮我写一首关于春天的诗。", "label": "通用知识"}

【训练】
  python -m scripts.train_intent
  TF-IDF（字符 1-2 gram）+ LogisticRegression，8:2 分层切分，
  产物 models/intent_clf.joblib；模型缺失时在线退化为纯关键词规则。
